## Теоретическая часть
**Двоичный поиск** — алгоритм поиска в отсортированном массиве, который на каждом шаге делит интервал поиска пополам. Сложность \(O(\log n)\). Требует отсортированных данных. Для вещественных чисел используется сравнение с погрешностью (epsilon).

**Хеш-таблица** — структура данных для реализации ассоциативного массива. Преобразует ключ в индекс с помощью хеш-функции. Коллизии разрешаются методами цепочек или открытой адресации. Средняя сложность операций \(O(1)\).

**Линейное пробирование** — метод разрешения коллизий, при котором при занятой ячейке ищется следующая свободная (с шагом 1). Прост в реализации, но подвержен первичной кластеризации.

## Описание реализованного алгоритма

### Двоичный поиск с погрешностью
Функция `binarySearchDouble` ищет элемент, разница которого с искомым не превышает `epsilon`. Условие `fabs(arr[mid] - target) <= epsilon` позволяет корректно работать с плавающей точкой.

### Хеш-таблица с линейным пробированием
Класс `HashTable` хранит массив структур `Entry` с полями `key`, `value`, `occupied`.
*   **Хеш-функция:** полиномиальная для строк: `hash = hash * 31 + c`.
*   **Вставка:** если ячейка занята, ищем следующую свободную `(hash + i) % size`.
*   **Поиск:** аналогично, пока не найдем ключ или пустую ячейку.
*   **Удаление:** реализовано с перестройкой таблицы для избежания проблем с поиском после удаления.

## Описание основных функций и структур данных
*   **`binarySearchDouble`, `binarySearchDoubleRecursive`** — двоичный поиск.
*   **`HashTable`** — класс хеш-таблицы.
*   **`insert`, `find`, `remove`** — основные операции.
*   **`measureBinarySearch`, `measureHashSearch`** — замер времени.

## Ответы на контрольные вопросы
<details>
<summary>1. Какое условие необходимо для применения двоичного поиска?</summary>
Массив должен быть отсортирован.
</details>

<details>
<summary>2. Какова сложность двоичного поиска? Почему она логарифмическая?</summary>
O(log n). Потому что на каждом шаге интервал поиска уменьшается вдвое.
</details>

<details>
<summary>3. В чём разница между итеративной и рекурсивной реализацией двоичного поиска?</summary>
Итеративная использует цикл и O(1) памяти. Рекурсивная использует стек вызовов и O(log n) памяти.
</details>

<details>
<summary>4. Чем опасен вариант mid = (left + right) / 2? Как правильно вычислять середину?</summary>
Опасен переполнением при больших значениях left и right. Правильно: `mid = left + (right - left) / 2`.
</details>

<details>
<summary>5. Что такое хеш-таблица? Из каких компонентов она состоит?</summary>
Это структура данных для ассоциативного массива. Компоненты: массив бакетов, хеш-функция.
</details>

<details>
<summary>6. Какие требования предъявляются к хеш-функции?</summary>
Детерминированность, равномерное распределение, быстрое вычисление.
</details>

<details>
<summary>7. Что такое коллизия в хеш-таблице? Как с ней бороться?</summary>
Ситуация, когда разные ключи дают одинаковый хеш. Борьба: метод цепочек, открытая адресация.
</details>

<details>
<summary>8. В чём отличие метода цепочек от открытой адресации?</summary>
Цепочки хранят коллизии в связном списке. Открытая адресация ищет следующую свободную ячейку в массиве.
</details>

<details>
<summary>9. Что такое первичная и вторичная кластеризация?</summary>
Первичная — при линейном пробировании (слипание занятых ячеек). Вторичная — при квадратичном пробировании (образование кластеров с одинаковым шагом).
</details>

<details>
<summary>10. Какова средняя и худшая сложность операций в хеш-таблице?</summary>
Средняя O(1), худшая O(n).
</details>

<details>
<summary>11. Когда эффективнее использовать двоичный поиск, а когда - хеш-таблицу?</summary>
Двоичный поиск — если данные отсортированы и нужно искать в статическом массиве. Хеш-таблица — если нужны быстрые вставки, удаления и поиск в динамическом наборе.
</details>

<details>
<summary>12. Что такое коэффициент загрузки хеш-таблицы? Почему он важен?</summary>
Отношение количества элементов к размеру таблицы. Важен для производительности: при высоком коэффициенте растет число коллизий.
</details>

<details>
<summary>13. Как работает рехеширование (динамическое расширение хеш-таблицы)?</summary>
При достижении порога заполнения создается новая таблица большего размера, и все элементы перехешируются.
</details>

<details>
<summary>14. Как выбрать размер хеш-таблицы? Почему часто выбирают простое число?</summary>
Размер выбирают так, чтобы коэффициент загрузки был ~0.7. Простое число уменьшает коллизии при использовании деления по модулю.
</details>

<details>
<summary>15. Как реализовать хеш-функцию для строк?</summary>
Полиномиальная: `hash = hash * 31 + c` (или с другим простым числом).
</details>
