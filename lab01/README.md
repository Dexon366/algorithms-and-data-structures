
## Цель работы

Изучить основные виды отношений между классами в объектно-ориентированном программировании: композицию и агрегацию, а также научиться использовать статические поля и методы классов. На практике реализовать систему управления таксопарком с использованием агрегации, статических счётчиков и паттерна «Одиночка» (Singleton).

## Теоретическая часть

### Композиция

Композиция — это отношение между объектами по принципу «часть–целое», при котором часть не может существовать независимо от целого. Время жизни части связано с временем жизни объекта, который её содержит.

При композиции целый объект отвечает за создание и уничтожение своих частей. Поэтому при уничтожении целого его составные части также уничтожаются.

В C++ композицию можно реализовать, например, через поля-объекты:

```cpp
class House {
private:
    Room livingRoom;
    Room kitchen;
};
```

В данном случае объекты `Room` являются частью `House` и существуют вместе с ним.

### Агрегация

Агрегация также представляет отношение «часть–целое», но части при этом могут существовать независимо от целого.

В C++ агрегацию можно реализовать с помощью указателей или ссылок. Например, класс может хранить указатель на объект другого класса, но не удалять этот объект в своём деструкторе.

В данной лабораторной работе `TaxiCompany` агрегирует объекты `Car` и `Driver`. Автомобили и водители создаются отдельно от таксопарка и продолжают существовать после его уничтожения.

Главное отличие агрегации от композиции заключается во времени жизни объектов: при композиции часть уничтожается вместе с целым, а при агрегации часть может продолжать существовать самостоятельно.

### Статические члены класса

Статическое поле принадлежит самому классу, а не отдельному объекту. Поэтому существует только один экземпляр такого поля, общий для всех объектов класса.

Статические поля удобно использовать для подсчёта количества созданных объектов. Например, в программе используются статические поля `driverCount` и `carCount`, которые хранят количество существующих водителей и автомобилей.

При создании объекта соответствующий счётчик увеличивается:

```cpp
driverCount++;
```

При уничтожении объекта счётчик уменьшается:

```cpp
driverCount--;
```

Для доступа к статическому полю используются статические методы. Например:

```cpp
Driver::getDriverCount();
Car::getCarCount();
```

Статические методы можно вызывать без создания отдельного объекта класса.

### Паттерн «Одиночка» (Singleton)

Singleton — это паттерн проектирования, который гарантирует существование только одного экземпляра определённого класса.

В лабораторной работе Singleton используется для класса `TaxiCompany`. Конструктор класса является приватным, поэтому создать объект таксопарка напрямую нельзя. Получение единственного экземпляра осуществляется через статический метод `getInstance()`.

Если объект ещё не создан, метод создаёт его. При последующих вызовах возвращается указатель на тот же объект.

Для запрета создания копий используются удалённые конструктор копирования и оператор присваивания.

## Ответы на контрольные вопросы

### 1. Что такое композиция? Приведите пример.

Композиция — это отношение «часть–целое», при котором часть не может существовать без целого. Целый объект управляет временем жизни своих частей.

Например, дом может состоять из комнат. Если объект дома уничтожается, его комнаты также уничтожаются.

### 2. Что такое агрегация? Чем она отличается от композиции?

Агрегация — это отношение «часть–целое», при котором части могут существовать независимо от целого.

Основное отличие от композиции заключается во времени жизни объектов. При композиции часть существует только вместе с целым, а при агрегации часть может существовать после уничтожения целого.

В данной работе таксопарк агрегирует автомобили и водителей. Если таксопарк уничтожить, автомобили и водители продолжают существовать.

### 3. Как реализовать композицию в C++? Приведите пример кода.

Композицию можно реализовать, если один класс содержит объект другого класса как своё поле:

```cpp
class Room {
};

class House {
private:
    Room room;
};
```

В этом случае объект `Room` является частью объекта `House`.

### 4. Как реализовать агрегацию в C++? Приведите пример кода.

Агрегацию можно реализовать с помощью указателя или ссылки на объект, созданный независимо от класса-целого:

```cpp
class Driver {
};

class TaxiCompany {
private:
    vector<Driver*> drivers;
};
```

Объекты `Driver` создаются отдельно, а `TaxiCompany` только хранит указатели на них и не удаляет их при своём уничтожении.

### 5. В чём разница между временем жизни частей при композиции и агрегации?

При композиции время жизни части связано с временем жизни целого. При уничтожении целого его части также уничтожаются.

При агрегации часть имеет независимое время жизни. Уничтожение целого не приводит к уничтожению объектов, которые оно агрегирует.

### 6. Что такое статическое поле класса? Чем оно отличается от обычного поля?

Статическое поле принадлежит классу в целом и существует в одном экземпляре для всех объектов этого класса.

Обычное поле принадлежит конкретному объекту. Поэтому каждый объект имеет собственную копию обычного поля.

Например, `name` у каждого водителя свой, а `driverCount` является общим для всех водителей.

### 7. Как объявить и определить статическое поле? Где оно хранится?

Внутри класса статическое поле объявляется с ключевым словом `static`:

```cpp
class Driver {
private:
    static int driverCount;
};
```

Затем поле определяется за пределами класса:

```cpp
int Driver::driverCount = 0;
```

В программе оно является общим для всех экземпляров класса.

### 8. Что такое статический метод? Можно ли из него обратиться к нестатическим полям?

Статический метод принадлежит классу и может быть вызван без создания объекта.

Например:

```cpp
Driver::getDriverCount();
```

Непосредственно обратиться к нестатическим полям из статического метода нельзя, потому что статический метод не относится к конкретному объекту.

### 9. Для чего используются статические счётчики объектов?

Статические счётчики используются для хранения количества существующих объектов определённого класса.

В данной работе `driverCount` подсчитывает количество водителей, а `carCount` — количество автомобилей.

Счётчик увеличивается в конструкторе и уменьшается в деструкторе.

### 10. Что такое паттерн «Одиночка» (Singleton)? Для чего он нужен?

Singleton — это паттерн проектирования, который обеспечивает существование только одного экземпляра класса.

В данной лабораторной работе Singleton используется для класса `TaxiCompany`, чтобы в программе существовал только один объект таксопарка.

Получение объекта выполняется через статический метод `getInstance()`.

### 11. Как запретить создание копий объекта (конструктор копирования)?

В C++ можно удалить конструктор копирования и оператор присваивания:

```cpp
TaxiCompany(const TaxiCompany&) = delete;
TaxiCompany& operator=(const TaxiCompany&) = delete;
```

После этого копирование объектов данного класса становится невозможным.

### 12. В каком порядке вызываются конструкторы и деструкторы при композиции?

При создании объекта сначала создаётся целый объект и его составные части, а при уничтожении сначала уничтожаются составные части, после чего завершается уничтожение целого объекта.

Это связано с тем, что части входят в состав целого и их время жизни связано с ним.

### 13. Можно ли изменить статическое поле из обычного метода?

Да. Обычный метод имеет доступ к статическим полям класса.

Например, в деструкторе класса `Driver` можно уменьшить статический счётчик:

```cpp
driverCount--;
```

При этом изменяется общее значение счётчика для всего класса.

### 14. Почему статические поля нужно определять вне класса?

Определение статического поля вне класса необходимо для создания его единственного экземпляра и выделения для него памяти.

Например:

```cpp
class Car {
private:
    static int carCount;
};

int Car::carCount = 0;
```

Первое объявление сообщает классу о существовании поля, а второе определяет само поле.

### 15. В каких случаях стоит использовать композицию, а в каких — агрегацию?

Композицию стоит использовать, когда часть является неотделимой частью целого и не должна существовать самостоятельно. Например, комнаты могут рассматриваться как части конкретного дома.

Агрегацию стоит использовать, когда объекты связаны между собой, но могут существовать независимо. Например, водитель и автомобиль могут существовать отдельно от таксопарка.

В данной работе используется агрегация, поскольку автомобили и водители существуют независимо от объекта `TaxiCompany`.

Также были изучены статические поля и методы. В программе реализованы счётчики количества автомобилей и водителей, которые изменяются при создании и уничтожении объектов.

Для класса `TaxiCompany` был реализован паттерн «Одиночка» (Singleton), благодаря которому в программе существует только один экземпляр таксопарка. Дополнительно была реализована проверка `nullptr` при добавлении автомобилей и водителей.

В результате были получены практические навыки создания взаимосвязанных классов, работы с указателями, управления временем жизни объектов, использования статических членов класса и реализации простого паттерна проектирования Singleton.
