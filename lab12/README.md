## Теоретическая часть
**Алгоритм Дейкстры** — жадный алгоритм поиска кратчайших путей от одной вершины до всех остальных. Работает только с неотрицательными весами. С `priority_queue` сложность \(O((V+E)\log V)\).

**Алгоритм Флойда-Уоршелла** — динамическое программирование для поиска кратчайших путей между всеми парами вершин. Сложность \(O(V^3)\). Допускает отрицательные веса (но не отрицательные циклы).

## Описание реализованного алгоритма

### Дейкстра с priority_queue
Используется `priority_queue<pair<int,int>, vector<...>, greater<...>>` для извлечения вершины с минимальным расстоянием. Массив `prev` хранит предшественника для восстановления пути. При извлечении устаревшей записи (если расстояние больше текущего `dist`) — пропускаем.

### Флойд-Уоршелл с next
Матрица `dist` инициализируется весами рёбер. Три вложенных цикла: `k` (промежуточная вершина), `i`, `j`. Если `dist[i][k] + dist[k][j] < dist[i][j]`, обновляем `dist` и `next[i][j] = next[i][k]`. Восстановление пути: идем по `next`, пока не достигнем конечной вершины.

### Обнаружение отрицательных циклов
После Флойда проверяем диагональ: если `dist[i][i] < 0` для какой-то `i`, значит, есть отрицательный цикл.

## Описание основных функций и структур данных
*   **`Graph`** — класс ориентированного взвешенного графа.
*   **`dijkstraWithPath`** — алгоритм Дейкстры.
*   **`getPath`** — восстановление пути по `prev`.
*   **`floydWarshall`** — алгоритм Флойда-Уоршелла.
*   **`generateRandomGraph`** — генерация случайного графа.

## Анализ сложности
| Алгоритм | Время | Память |
| :--- | :--- | :--- |
| Дейкстра (priority_queue) | O((V+E) log V) | O(V) |
| Флойд-Уоршелл | O(V^3) | O(V^2) |

## Ответы на контрольные вопросы
<details>
<summary>1. Какие условия должны выполняться для корректной работы алгоритма Дейкстры?</summary>
Все веса рёбер должны быть неотрицательными.
</details>

<details>
<summary>2. Почему алгоритм Дейкстры не работает с отрицательными весами?</summary>
Потому что он жадно выбирает минимальное расстояние и не пересматривает его. Отрицательное ребро может уменьшить расстояние до уже обработанной вершины.
</details>

<details>
<summary>3. Какова временная сложность алгоритма Дейкстры с приоритетной очередью?</summary>
O((V+E) log V).
</details>

<details>
<summary>4. В чём заключается идея алгоритма Флойда-Уоршелла?</summary>
Динамическое программирование: на каждом шаге разрешаем использовать вершину k как промежуточную и обновляем расстояния.
</details>

<details>
<summary>5. Какова временная сложность алгоритма Флойда-Уоршелла?</summary>
O(V^3).
</details>

<details>
<summary>6. Как алгоритм Флойда-Уоршелла обнаруживает отрицательные циклы?</summary>
После выполнения проверяем диагональ матрицы расстояний: если dist[i][i] < 0, есть отрицательный цикл.
</details>

<details>
<summary>7. В каких случаях предпочтительнее использовать алгоритм Дейкстры?</summary>
Когда нужны расстояния от одной вершины до всех остальных, и граф разреженный.
</details>

<details>
<summary>8. В каких случаях предпочтительнее использовать алгоритм Флойда-Уоршелла?</summary>
Когда нужны расстояния между всеми парами вершин, граф небольшой (V ≤ 400-500), или есть отрицательные веса.
</details>

<details>
<summary>9. Как восстановить кратчайший путь после выполнения алгоритма Дейкстры?</summary>
Использовать массив prev, в котором для каждой вершины хранится предшественник. Идти от конца к началу, затем развернуть.
</details>

<details>
<summary>10. Как восстановить кратчайший путь после выполнения алгоритма Флойда-Уоршелла?</summary>
Использовать матрицу next, где next[i][j] — следующая вершина после i на пути к j. Идти по next, пока не достигнем j.
</details>

<details>
<summary>11. Что такое релаксация в контексте алгоритмов поиска кратчайших путей?</summary>
Операция обновления расстояния: если dist[u] + weight(u,v) < dist[v], то dist[v] = dist[u] + weight(u,v).
</details>

<details>
<summary>12. Как можно оптимизировать алгоритм Дейкстры для разреженных графов?</summary>
Использовать priority_queue (кучу) вместо линейного поиска минимума. Сложность снижается с O(V^2) до O((V+E)log V).
</details>

<details>
<summary>13. Какую память требует алгоритм Флойда-Уоршелла?</summary>
O(V^2) для матрицы расстояний (и O(V^2) для next).
</details>

<details>
<summary>14. При каком количестве вершин алгоритм Флойда-Уоршелла становится неприменимым?</summary>
При V > 1000-2000 (O(V^3) становится слишком медленным для реального времени).
</details>

<details>
<summary>15. Как модифицировать алгоритм Дейкстры для нахождения второго кратчайшего пути?</summary>
Хранить два массива расстояний (первое и второе) и обновлять их при релаксации, либо использовать модифицированную priority_queue с двумя лучшими значениями для каждой вершины.
</details>
